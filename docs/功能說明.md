# AI 許願池 — 功能說明

面向：管理者／維運人員。說明各專區用途、用字定位，以及需要在 Supabase 做的設定。

---

## 專區總覽

| 專區 | 路徑 | 用途 |
|------|------|------|
| 首頁 | `/` | 入口與流程說明 |
| 我要許願 | `/wish` | 同仁提出需求（困擾） |
| 公告欄 | `/board` | 瀏覽所有需求、按「我也有這個困擾」、對**已導入**需求評論評分 |
| 主題討論 | `/topics` | 依主題開串，討論、留言、回應 |
| 成果看板 | `/impact` | 呈現處理進度與成果（含已結案／暫不處理），展示同仁**評論** |
| 管理員專區 | `/admin` | 後台管理需求、評論、主題（需密碼） |

---

## 用字定位（重要）

為避免混淆，三個互動專區的用字明確分工：

- **主題討論** ＝ 討論／**留言**／回應
- **公告欄／成果看板** ＝ **評論**（評分＋文字，僅限已導入的成果）

> 過去「回饋」一詞同時用在成果看板與主題討論，容易混淆。現已全面統一：
> 對成果的評分回應一律稱「**評論**」，主題裡的交流一律稱「**留言／討論**」。

---

## 需求狀態與「結案」

狀態流程：已收到 → 整理中 → 評估中 → 尋找工具中 → 測試中 → **已導入**／**暫不處理**。

- **結案（終態）＝「已導入」＋「暫不處理」**。前者是有解法落地，後者是評估後決定先不做；兩者都不算「處理中」，也不會互為前後步驟。
- 判斷邏輯統一放在 `types/submission.ts` 的 `CLOSED_STATUSES` / `isClosedStatus()`，新增終態狀態時只改這裡。
- **成果看板**：KPI 顯示「已結案率」＝（已導入＋暫不處理）÷ 總需求數，副標補上已結案件數與其中暫不處理幾件；下方另有「**評估後暫不處理**」清單，列出公開的暫不處理需求＋數位創新處的處理說明，讓同仁知道為什麼不做。
- **管理後台**：狀態篩選除了單一狀態，另提供「未結案」「已結案（已導入＋暫不處理）」兩個群組選項。
- 暫不處理不等於永久拒絕；情況有變或有新資訊時可改回其他狀態重新開案。
- 成果看板兩份清單（已導入／暫不處理）的標題都可點擊，連到 `/board?id=<需求 id>`，公告欄會直接打開該則需求的詳情視窗；關閉視窗時會清掉網址參數。這個網址也可以直接分享給同仁。

## 公告欄 × 主題討論的連動

需求在「已導入」之前不該被評分，因此：

- **已導入**的需求 → 公告欄詳情頁顯示「評論」框（星等＋文字），內容會出現在成果看板。
- **暫不處理**的需求 → 不顯示評分框，改為說明「已評估後暫不處理、已先結案」＋「**討論這則需求**」按鈕（有新資訊可補充，我們會重新評估）。
- **其他未導入**的需求 → 不顯示評分框，改為「**討論這則需求**」按鈕：
  - 點擊後，系統會**自動取得或建立**這則需求專屬的討論串（標題＝需求標題），並跳進去，使用者**只要寫留言**即可。
  - 同一則需求大家的討論會集中在**同一串**，不會重複開串。
  - 這種「來自需求」的主題，在主題討論列表與串頁會標示「**需求討論**」（副色）與「來自公告欄需求」。

官方（數位創新處）開的、或系統自動建立而沒有具體負責人員的主題／留言，頭像旁統一顯示「**管理者**」，並附「數位創新處」標記。

## 資料表（Supabase）

| 資料表 | 說明 |
|--------|------|
| `submissions` | 需求（許願）主體，含 `status`（已收到／整理中／…／已導入／暫不處理，後兩者皆為結案） |
| `feedbacks` | 評論（星等＋文字），`submission_id` 指向被評論的需求 |
| `topics` | 主題討論串。`submission_id` 有值＝由某則需求衍生的討論串；null＝一般主題 |
| `topic_posts` | 主題底下的留言／回覆（`parent_id` 有值＝回覆） |

`topics.submission_id` 上有 partial unique index，確保一則需求最多只綁一個討論串。

---

## 部署 / 設定注意事項

程式上線前，需在 **Supabase SQL Editor** 執行以下 SQL（各執行一次即可，可安全重複執行）：

1. `sql/topics.sql` — 建立／補齊 `topics`、`topic_posts`，含 `submission_id` 欄位與 unique index。
2. `sql/feedbacks.sql` — 建立 `feedbacks`。
3. `sql/migrate-feedbacks-to-topics.sql` —（一次性）把「未導入需求」上有文字的舊評論搬到主題討論；純星等評論則清除。

> ⚠️ 若程式已上線但 `topics.submission_id` 欄位尚未建立，公告欄的「討論這則需求」會失敗。務必先跑 SQL 再部署，或部署後立即補跑。

## 其他

- 留言／評論／主題說明中的網址（http/https）會自動變成可點連結，並在新分頁開啟。
- 主題討論列表可用「排序」（由新至舊／由舊至新）與「需求討論」標籤篩選。
