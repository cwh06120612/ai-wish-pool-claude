## 2026-10-29

### 程式碼搬到公司 GitHub
- 程式碼從個人帳號搬到公司的 GitHub（`Fengyu-IT-Team/ai-wish`），過去的修改紀錄都保留。網站功能沒有任何改變。

### 主題討論：留言和回覆可以附圖片
- 主留言框和每則留言的回覆框旁邊多了「**圖片**」按鈕，可以選電腦或手機裡的圖片；也可以在輸入框裡**直接貼上截圖**（Ctrl+V）。
- 每則留言最多 4 張圖。送出前會先顯示縮圖，點縮圖右上角的 ✕ 可以拿掉。
- 只放圖片、不打字也可以送出。
- 留言裡的圖片以縮圖顯示，點了會開新分頁看原圖。管理後台的主題討論也看得到圖片。
- 手機拍的大照片會在上傳前自動縮小（長邊最多 1920 像素），上傳比較快，也比較省空間。
- 編輯留言時只能改文字，圖片不能增減；要換圖片請刪掉重發。
- **需要跑 SQL**：執行 `sql/topic-images.sql`（建立存圖片的空間，並在留言加上圖片欄位）。沒跑之前，純文字留言照常可用，附圖送出會顯示「圖片上傳失敗」。

### 主題討論：可以刪除自己的留言
- 自己發的留言和回覆，「編輯」旁邊多了「**刪除**」（兩者都是圖示按鈕，滑過會顯示文字）。按下去會跳出確認視窗，顯示要刪的留言內容，按「刪除」才會真的刪掉；按「取消」、Esc 或點視窗外面都可以放棄。
- 和編輯一樣，只有在這台瀏覽器發出的留言才看得到刪除按鈕。
- **已經有人回覆的留言不能刪**（刪除鍵變灰，滑過會說明原因），因為主留言刪掉時，底下別人的回覆也會一起消失。這種情況請改用編輯。
- 刪除留言時，附的圖片檔也會一起從儲存空間刪掉（後台刪除留言也是）。
- **需要跑 SQL**：重新執行 `sql/topic-images.sql`（新增刪除圖片檔的權限）。沒跑之前，留言照樣刪得掉，只是圖片檔會留在儲存空間裡。

### 回覆只有最新一則可以刪除
- 回覆只有一層，大家要接著回某則回覆時，也是繼續在同一串往下回，所以後面的回覆可能是在回前一則。為了不讓後面的回覆變得看不懂，**同一串回覆中只有最新的那則可以刪除**；前面的回覆刪除鍵會變灰，滑過顯示「後面已有新的回覆，只能刪除最新一則」。
- 主留言的規則不變：已有人回覆就不能刪。

### 編輯留言不能把文字清空
- 原本有附圖的留言，編輯時把文字全部刪掉還是能儲存，留言就只剩圖片。現在只要原本有文字，清空後「儲存」按鈕會變灰，並提示「留言內容不能清空」。
- 原本就只有圖片、沒有文字的留言不受影響，可以照常編輯（例如補上文字）。

### 留言圖片改用燈箱看大圖
- 點留言裡的圖片縮圖，不再開新分頁，改成在原頁面用黑色半透明底的「燈箱」放大顯示（樣式和 AI 資源平台一致）。
- 上方顯示目前是第幾張（如「2 / 3」），右上有「下載」和關閉按鈕；同一則留言有多張圖時，可用左右箭頭按鈕或鍵盤 ← → 翻頁。
- 按 Esc 或點圖片以外的黑色區域就會關閉。

### 滑過提示改用網站自己的樣式
- 滑鼠移到某些文字或圖示上時出現的說明，原本是瀏覽器內建的灰色小框（樣式各瀏覽器不同，也要停一下才出現）。現在改成和後台圖表提示一樣的白底圓角小框，滑過就立刻出現。
- 套用位置：公告欄卡片的煩人程度色點、主題討論的「已編輯」與「圖片」按鈕、後台橫條圖的項目名稱。

- 同仁反映打字時不小心按到 Enter，留言就送出去了。現在**自己發的留言和回覆**旁邊會出現「**編輯**」按鈕，點了可以直接改內文，按「儲存」送出、「取消」或 Esc 放棄。

- **需要跑 SQL**：重新執行 `sql/topics.sql`（新增 `topic_posts.updated_at` 欄位與修改權限）。沒跑之前，按「儲存」會顯示儲存失敗。

### 狀態改名：「暫不處理」→「不予處理」
- 「暫」字會讓同仁以為之後一定會回來處理，但實務上有一部分是評估後確定不做，容易造成誤解，因此改名為「**不予處理**」（仍然是結案的一種，和「已導入」並列終態）。
- 前台文案一併調整：公告欄詳情改為「這則需求評估後不予處理，已結案」，並補上常見原因（重複、目前不適合用 AI 解、已有其他做法）；成果看板區塊改為「**評估後不予處理**」。
- 明確保留重啟可能：「不予處理不等於永久拒絕，情況有變或有新資訊可到討論串補充，我們會重新評估、必要時重新開案。」
- 後台狀態選單、篩選群組（已結案＝已導入＋不予處理）、狀態流程圖同步改名。
- **需要跑 SQL**：`sql/rename-status-defer.sql`（把既有資料的「暫不處理」更新為「不予處理」）。沒跑之前，舊資料會被新版程式當成未結案／處理中。

## 2026-07-28

### 「暫不處理」也算結案
- 需求狀態新增**結案**的概念：**已導入**（有解法落地）與**暫不處理**（評估後先不做）都算結案，只是結果不同；兩者都不再算「處理中」。
- **成果看板**：第 4 張 KPI 由「導入完成率」改為「**已結案率**」（＝（已導入＋暫不處理）÷ 總需求數，維持百分比呈現），副標顯示「已導入 X・暫不處理 Y」拆解件數。
- **成果看板**新增「**評估後暫不處理**」清單區塊（只列公開的需求），每則附上數位創新處的處理說明；未填說明時顯示提示語。區塊底部說明「暫不處理不代表不重要，情況有變會重新開案」。
- **成果看板**「已經幫大家解決的事」與「評估後暫不處理」的**整列**都可以點擊，直接跳到公告欄該則需求並打開詳情視窗（列內的「評論」按鈕、處理說明裡的網址照原本行為運作，不會誤跳）；網址格式為 `/board?id=<需求 id>`，關掉視窗會自動把參數清掉。
- **公告欄**選「全部」時不再依煩人程度切成一塊一塊（麻痺／很煩／…），改成依**排序條件**分組：
  - 由新至舊／由舊至新 → 依「**年 / 月**」分組（如「2026 年 7 月・12 則」）。
  - 最多認同 → 依**認同數每 10 個一級**分組（「21–30 個認同」、「11–20 個認同」、「1–10 個認同」，尚無認同者自成一組）。
  - 點特定煩人程度標籤時，仍顯示該程度的單一區塊（不分組）。
- **公告欄**卡片在標題前加一個**煩人程度色點**（顏色取徽章底色與主色之間的中間調，滑過顯示完整敘述），配合「全部」不分區塊後仍看得出嚴重度；詳情視窗照舊顯示完整標籤。
- **公告欄**卡片不再顯示「痛點」標籤，改成點開詳情視窗才列出（卡片只留標題、狀態、提出人／日期、認同數）。
- **公告欄**詳情頁：暫不處理的需求不再顯示「這則需求還在處理中」，改為「**這則需求評估後暫不處理，已先結案**」，仍可點「討論這則需求」補充新資訊。
- 由暫不處理需求自動建立的討論串，預設說明文字改為結案版本（原本會誤寫成「還在處理中」）。
- **管理後台**：狀態篩選新增「**未結案**」「**已結案（已導入＋暫不處理）**」兩個群組選項；狀態流程圖中「已導入 → 暫不處理」的箭頭改為「或」，並在下方標註已結案件數。
